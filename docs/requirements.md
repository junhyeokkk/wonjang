# 요구사항 (AC 목록)

> **정본 위치**: Notion「원장 (wonjang) - 복식부기 원장 서버 / 02 요구사항·기능 명세」.
> 이 파일은 레포만 봐도 AC 번호가 뭘 의미하는지 알 수 있도록 **미러링**해둔 것.
> AC 를 추가·수정할 때는 **Notion 02 를 먼저 바꾸고 이 파일을 갱신**한다 (반대 금지).

## 기능 목록

| # | 기능 | 우선순위 | 주차 |
|---|---|---|---|
| F1 | 계정과목 등록·조회 | 필수 | 1 |
| F2 | 전표 입력 (균형 검증) | 필수 | 1~2 |
| F3 | 원장 조회 + 잔액 | 필수 | 2 |
| F4 | 역분개 정정 | 필수 | 3 |
| F5 | 시산표 | 필수 | 3 |
| F6 | 일마감 잔액 스냅샷 | 성능 | 4 |
| F7 | 멱등성 키 | 안정성 | 4 |

## 수용기준 (AC)

각 항목이 테스트 하나. 테스트 이름 접두어로 `ac04_…` 형태 사용.

### F1 계정과목

- **AC-01** 코드(예: `1010`) · 이름 · 유형(ASSET/LIABILITY/EQUITY/REVENUE/EXPENSE)으로 등록된다
- **AC-02** 같은 코드로 두 번 등록하면 409 — DB UNIQUE 가 막는다
- **AC-03** 분개가 하나라도 있는 계정은 비활성화만 가능, 삭제 불가

### F2 전표 입력

- **AC-04** 분개 2줄 이상, 차변 합 = 대변 합이면 201 + 전표 번호
- **AC-05** 차변 ≠ 대변이면 422, 어느 쪽이 얼마 모자란지 응답에 포함
- **AC-06** 서비스 검증을 우회해 DB 에 직접 불균형 분개를 넣어도 DB 가 거부한다 (deferred constraint / 트리거)
- **AC-07** 분개 중 하나라도 실패하면 전표 전체가 롤백 (부분 저장 0 건)
- **AC-08** 금액은 0 초과의 정수(원 단위), 음수 · 0 거부
- **AC-09** 비활성 계정으로는 분개 불가

### F3 원장 · 잔액

- **AC-10** 계정 원장은 전표일↑, 같은 날짜면 생성순↑, 각 줄에 누적 잔액 포함
- **AC-11** 기간 (from~to) 필터 시 기초 잔액(from 이전 누적)을 첫 줄로 포함
- **AC-12** 잔액은 계정 유형에 따라 부호 방향이 다르다 (ASSET/EXPENSE 는 차변 +, 나머지는 대변 +)

### F4 역분개

- **AC-13** `POST /vouchers/{id}/reverse` 하면 차변↔대변 반전된 새 전표가 생성되고 원본은 그대로
- **AC-14** 역분개 전표는 원본 id 를 `reverses_voucher_id` 로 가리킨다
- **AC-15** 이미 역분개된 전표를 또 역분개하면 409
- **AC-16** `entries` 에 UPDATE 또는 DELETE 를 실행하면 DB 트리거가 예외를 던진다 (`PUT /entries` 같은 API 도 없음)
- **AC-27** 역분개 전표를 다시 역분개하면 422 (`CANNOT_REVERSE_REVERSAL`)
- **AC-28** 역분개 일자는 기본 요청일이며 마감일 이후여야 한다 (원본이 마감 기간이어도 역분개 가능)

### F5 시산표

- **AC-17** 기준일 입력 시 전 계정의 차변 합 · 대변 합 · 잔액 목록 + 총합 2개
- **AC-18** 총합 불일치 시 `balanced: false` 와 차이액 — 정상이라면 절대 발생 안 해야 함 (테스트에서 일부러 만들어 확인)

### F6 스냅샷

- **AC-19** 일마감 실행 시 계정별 마감 잔액이 `balance_snapshots` 에 저장
- **AC-20** 잔액 조회는 최근 스냅샷 + 이후 분개만 합산, 전체 합산과 결과 동일 (동등성 테스트)
- **AC-21** 마감일 이전 날짜로 전표 입력 시 422 (마감 잠금)

### F7 멱등성

- **AC-22** `Idempotency-Key` 헤더가 같은 요청을 두 번 보내면 두 번째는 첫 응답을 그대로 반환, 전표는 1개
- **AC-23** 같은 키에 다른 본문이면 422

### 비기능

- **AC-24** 100 스레드가 같은 계정에 동시 전표 입력 → 전부 성공하고 시산표 균형
- **AC-25** 모든 에러 응답은 `{code, message, detail}` 형식 통일
- **AC-26** 모든 쓰기 API 는 요청자(`X-User-Id`)와 시각을 기록
