# ADR-001: 금액은 부동소수점이 아닌 정수(BIGINT)로 저장한다

- 날짜: 2026-06-11
- 상태: 승인됨

## 맥락 (Context)

원장의 모든 금액을 어떤 타입으로 저장할지 결정해야 한다. 금액 연산에서 1원의 오차도
허용되지 않으며, "거래의 합 = 0" 불변식 검증이 정확해야 한다.

## 검토한 선택지 (Options)

1. **FLOAT / DOUBLE** — 연산이 빠르지만 이진 부동소수점 특성상 0.1 + 0.2 ≠ 0.3 류의
   오차가 발생한다. 금액 저장에 사용 불가.
2. **NUMERIC / DECIMAL** — 정확한 십진 연산이 가능하다. 다만 애플리케이션 레이어(JS)로
   넘어오면 number 또는 문자열로 다뤄야 하고, JS number는 2^53 이상에서 정밀도를 잃는다.
3. **BIGINT (최소 화폐 단위 정수)** — KRW는 소수점이 없으므로 원 단위 정수로 손실 없이
   표현 가능. 애플리케이션에서는 TypeScript `bigint`로 매핑해 정밀도 문제를 차단한다.

## 결정 (Decision)

**BIGINT를 사용하고, 금액은 통화의 최소 단위 정수로 저장한다.** (KRW = 원, 추후 USD
지원 시 = 센트)

애플리케이션 레이어에서는 `number`가 아닌 `bigint`로 다루며, DTO 직렬화 시 문자열로
변환한다.

## 결과 (Consequences)

- 얻는 것: 연산 오차 원천 차단, "합 = 0" 검증의 단순화 (`SUM(amount) = 0`)
- 트레이드오프: 화면 표시용 포맷팅(콤마, 통화 기호)을 항상 별도 처리해야 함.
  JSON 직렬화 시 bigint 처리 보일러플레이트 필요
- 재검토 조건: 소수점이 있는 통화(USD 등) 멀티 커런시 지원 시, 통화별 최소 단위
  메타데이터(`currency_exponent`) 도입을 함께 검토한다
